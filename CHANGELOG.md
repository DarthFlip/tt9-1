# Changelog

All notable changes to this project are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Note: this file was created part-way through the fork's life. Sections below cover
work done in this fork on top of upstream `sspanak/tt9`; earlier upstream history is
recorded in the upstream project's own release notes. The most recent tag in this
repo is `v61.0` — the 62.x builds distributed to MegaLife devices were never tagged.

## [Unreleased]

### Fixed
- Key presses are no longer swallowed when the dictionary fails to import. A failed
  import used to clear its own 20-minute retry cooldown, so every subsequent key
  press started another doomed import and was consumed by it instead of typing a
  digit — the keyboard showed "Please wait for the dictionary to load" indefinitely
  and accepted no input at all. Failed imports now respect the cooldown.
- The dictionary loads again after installing a build whose version code is lower
  than the one already on the phone. The database schema version is the app's
  version code, which is derived from the branch's commit count and so is not
  always increasing; SQLite refused to open the database at all, every dictionary
  import failed with "Can't downgrade database from version 1700 to 1665", and the
  keyboard offered no words. Existing custom words and learned frequencies are kept.
- The keyboard no longer runs out of memory and crashes on Hebrew. The vocabulary
  used for glide typing and typo correction is now capped at the 200,000 most
  frequent words per language instead of loading entire dictionaries into memory.
  Hebrew ships about 1.5 million words, and with English and Yiddish also resident
  that filled the whole 256 MB heap available to the keyboard — so users hit
  `OutOfMemoryError`, frozen input and "keyboard is not responding" dialogs. English
  and Yiddish are unaffected by the cap; both are smaller than it.

### Added
- Release builds are platform-signed against the MegaLife shared platform key.
  Pass `-Pplatformkey=<phone>`; release packaging fails loudly without it, so an
  app can never be signed with the wrong key by accident.
- `-Pversion=X.Y.Z` and `-PversionCode=NNNN` Gradle overrides, so a build can be
  versioned for a release without adding a tag to the tree.
- Optional local-only crash reporting and anonymous usage telemetry, enabled only
  on developer machines that provide `app/local-instrumentation.gradle`. A public
  checkout has no such file, compiles without the `src/local/java` sources, and the
  reflective bridge silently no-ops — public builds have no code path that touches
  the network.

### Changed
- The APK now bundles only the English, Hebrew and Yiddish dictionaries, cutting the
  bundled asset payload from roughly 216 MB to roughly 20 MB. Every other language is
  unchanged for the user and still downloads on first selection.
- Added the `INTERNET` permission, used only by the optional local-only crash
  reporting and telemetry described above.

### Fixed
- Release builds no longer fail with "uses input file(s) generated by
  ':app:bundleBigramSeed' without declaring it" — the bigram-seed task is now a
  declared input of the lint tasks that read merged assets.
